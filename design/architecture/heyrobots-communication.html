How heyrobots talks

You talk to a team of agents. The agents live on one or more of your machines, and a cloud server can be one of them. Your phone talks to one machine, the machines talk to each other, and each machine talks to the agents it runs. This page explains the ideas behind those conversations and how each one works.

The philosophy

Six rules decide every design choice below. When two of them pull apart, the earlier one wins.

You are the authority

Anything that reaches other people waits for your OK, given on your own device. Machines and agents propose; only you approve. Rules that every machine shares are changed by you, never by a vote between machines.

One team, wherever it runs

An agent on the cloud, the home Mac or the office box looks and behaves the same in the app. The only visible difference is whether its machine is up: available, working, or away since a time.

Every fact has one writer

Each message, reply and decision is written once, by the machine where it happened, and never edited. Other machines keep copies, which always end up identical. This is why no machine ever needs a majority to carry on.

Work happens at the agent's home

Only the machine an agent lives on runs it, holds its memory and sends what it writes. A task can never run twice, because only one machine is allowed to run it.

Fast by default

You see the agent thinking the moment you send. Steps that aren't needed are skipped: a direct chat goes straight to its agent, with no routing and no agreement step. Agents stay started and ready, and chat turns use a quick model.

Reach out, never in

Phones and machines only dial out. Links between machines use each machine's own key, checked both ways. Content from outside, such as an email or a web page, is treated as untrusted wherever it is read.

Four links

Everything heyrobots says travels over one of four links. Each has one job, and none of them needs to know how the others work.

LinkBetweenWhat it carriesHow it works
1 · AppYour device and one machineMessages you send, chats, approvals, live updatesHTTPS with a device token from pairing. A stream of events tells the app the moment a chat changes.
2 · Machine linkYour machinesWho is up, each machine's agent cards, and log entries the other side is missingMutual TLS, pinned to each machine's ed25519 key. A message's journey

This is what happens between pressing Send and seeing the answer. The times were measured on this Mac with two servers, both using omp with Claude Sonnet 5.5.

  1. Stored and shown thinking. The machine your device talks to stores the message once. A retry with the same message id is ignored. The app shows the agent thinking straight away, before anything else happens.
  2. Is there anything to decide? In a direct chat or with an @mention, the answer is no: the message goes straight to that agent. In a group or a new open chat, the lead picks who answers.
  3. Agreeing who decides, in shared chats only. Every machine holds a copy, so only one may route each message. The reachable machine with the newest copy claims it and routes as soon as every other machine has seen the claim. If two claims ever cross, every machine keeps the earliest one, and the other machine stands down before acting.
  4. Handing over. If the chosen agent lives on another machine, a hand-off entry goes into the log. That machine starts the task under its own rules.
  5. The work. The agent's home gives the task a warm process, sends the turn and gates its tools. A finished task in a chat stays finished. A new message starts new work, unless the agent is still waiting on your answer.
  6. The answer travels back. The reply is stored on the agent's machine, copied to the others within a second, and pushed to your app by the event stream.

The shared chat log

Machines never send each other commands. They only add entries to one log that every machine copies. Each entry carries its writer, a sequence number for that writer, and a hybrid clock: wall time plus a counter, so the order survives clocks that drift. Every machine sorts by that clock, then by writer, so all of them show the same order.

EntryWritten byWhat the others do with it

Why there is no voting

Raft and Paxos need a majority of machines to agree before anything happens. With a laptop and a cloud server, a majority means both, so closing the laptop would stop the cloud from answering. A personal cluster is often exactly that: two machines, one of them asleep.

heyrobots needs agreement on one question only: who routes this message. Everything else has a single writer by construction. A message has one sender, a task has one home, and a setting has one authority, you. The routing question is settled by the newest-copy claim, and the worst case is visible and harmless: during a network split, two agents might each answer once, and the chat marks the second answer as a duplicate. Outward actions can never double, because only the agent's home can send them.

When things go wrong

What happensWhat you seeWhat the system does
A machine is offIts agents show "away since 17:24"After 15 seconds of silence it is unreachable. Routing skips its agents, and work already handed to it waits until it is back.
The network splitsEach side keeps working with its own agentsLogs merge when the link returns; a double answer is marked.
A machine restarts mid-hand-offA short delayRecent hand-offs are rescanned every half second, so none is lost.
A new machine joinsYour old chats appear on itHistory arrives as already handled and is never routed or worked on again.
A machine is removedIts agents leave the teamThe removal spreads to every machine, and its key is refused from then on.
The agent stops answeringThe task says why, in the chatThe process is ended. Each task has its own process, so no other task is affected.

Not built yet

  • Inviting another person's machines into one chat.
  • Your phone switching to another machine when the one it is paired with is down.
  • Shared rules and spending caps across machines.
  • Showing the agent's real steps, such as "Reading 3 pages", in the thinking bubble. Today it says "Thinking", then "Working on it".
  • Keeping one agent session open across messages, which would save the agent re-reading its instructions on every turn.
